# Архитектура

Next.js App Router разделяет серверную загрузку данных и интерактивный слой. Страницы выпуска, статьи и архива получают данные на сервере. Защищённый layout `(reader)` проверяет Auth.js-сессию до чтения базы; публичная страница входа не получает данные выпуска. `IssueHome` отвечает только за фильтрацию, shuffle, раскрытие выдержек и layout-анимацию. Статья подключает небольшой клиентский модуль прогресса и share; основной текст остаётся Server Component.

PostgreSQL хранит `issues → stories → sources / x_posts`. Внешние ключи каскадно удаляют дочерние записи, уникальные ограничения защищают дату, slug, rank и единственную lead-статью. Command palette запрашивает авторизованный `/api/search` по заголовку, тексту, категории, названию и URL источника. Архив запрашивает лёгкие сводки постранично, по 60 выпусков.

При отсутствии `DATABASE_URL` production показывает пустой выпуск. Только локальный development при `AUTH_BYPASS_LOCAL=1` включает вымышленный образец с явной маркировкой. Editorial API никогда не использует образец и возвращает ошибку, если база не настроена.

Auth.js Credentials допускает только один заранее настроенный адрес, не содержит регистрации и хранит короткоживущую подписанную JWT-сессию. Editorial API имеет отдельный Bearer secret.
