# Архитектура

Next.js App Router разделяет серверную загрузку данных и интерактивный слой. Открытые страницы выпуска, статьи и архива получают данные на сервере. `IssueHome` отвечает только за фильтрацию, shuffle, раскрытие выдержек и layout-анимацию. Статья подключает небольшой клиентский модуль прогресса и share; основной текст остаётся Server Component.

PostgreSQL хранит `issues → stories → sources / x_posts`. Внешние ключи каскадно удаляют дочерние записи, уникальные ограничения защищают дату, slug, rank и единственную lead-статью. Command palette запрашивает публичный read-only `/api/search` по заголовку, тексту, категории, названию и URL источника. Архив запрашивает лёгкие сводки постранично, по 60 выпусков.

При отсутствии `DATABASE_URL` production показывает пустой выпуск. Локальный development без базы включает вымышленный образец с явной маркировкой. Editorial API никогда не использует образец и возвращает ошибку, если база не настроена.

Читательской авторизации нет. Editorial API имеет отдельный Bearer secret и выполняет все операции записи только на сервере.
